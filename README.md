# 2048DBZ

نسخة مستوحاة من لعبة **2048** تجمع بين أسلوب دمج المربعات وشخصيات وتحولات **Dragon Ball Z**. حرّك المربعات على الشبكة، واجمع مرحلتين متطابقتين لتصل إلى تحول أقوى، واستمر بعد الوصول إلى 2048 لتجربة المراحل الأعلى.

> المشروع لعبة ويب ثابتة تعمل مباشرة في المتصفح باستخدام HTML وCSS وJavaScript، ولا تحتاج إلى خادم خلفي أو قاعدة بيانات.

## المزايا

- شبكة لعب بحجم 4×4.
- دمج المربعات المتساوية للحصول على قيمة أعلى.
- شريط شخصيات Dragon Ball مخصص للعبة ومكوّن من 13 مرحلة.
- رسائل للفوز وانتهاء اللعب، مع إمكانية مواصلة اللعب بعد الفوز.
- عرض النقاط الحالية وأفضل نتيجة.
- حفظ أفضل نتيجة محليًا في المتصفح.
- تحريك باستخدام لوحة المفاتيح أو السحب باللمس.
- مؤثرات حركة ودمج، وتصميم يتكيف مع الشاشات الصغيرة.
- واجهة عربية وتعليمات لعب بالعربية.
- أصول محلية للصور والخطوط، دون حاجة إلى حزم JavaScript خارجية أو عملية بناء.

## طريقة اللعب

1. تبدأ اللعبة بمربعين على شبكة 4×4.
2. حرّك المربعات إلى الأعلى أو الأسفل أو اليمين أو اليسار.
3. عندما يصطدم مربعان يحملان القيمة نفسها، يندمجان في مربع واحد بقيمة مضاعفة.
4. تزداد النقاط بمقدار قيمة المربع الناتج من كل عملية دمج.
5. بعد كل حركة ناجحة، يظهر مربع جديد في موضع فارغ. قيمته 2 غالبًا، وقد تكون 4.
6. عند الوصول إلى المربع 2048 تظهر رسالة الفوز. يمكنك اختيار **مواصلة اللعب** لمتابعة الدمج إلى المراحل الأعلى، بما فيها 4096 و8192.
7. تنتهي الجولة عندما لا تبقى أي حركة ممكنة ولا توجد خلايا فارغة أو مربعات متجاورة قابلة للدمج.

لا تؤدي الحركة التي لا تغيّر أي موضع إلى إضافة مربع جديد أو تحديث اللوحة.

## التحكم

| الطريقة | التحكم |
| --- | --- |
| الأسهم | أعلى، أسفل، يمين، يسار |
| WASD | W للأعلى، A لليسار، S للأسفل، D لليمين |
| H / J / K / L | H لليسار، J للأسفل، K للأعلى، L لليمين |
| شاشة اللمس | اسحب على لوحة اللعبة باتجاه الحركة المطلوبة |
| Space | إعادة بدء الجولة |

تظهر أزرار **إعادة المحاولة** و**مواصلة اللعب** عندما تكون مناسبة لحالة اللعبة.

## حفظ النقاط

تُحفَظ أفضل نتيجة في **localStorage** باستخدام المفتاح **bestScore** داخل المتصفح.

- تبقى أفضل نتيجة عند بدء جولة جديدة في المتصفح نفسه.
- التخزين محلي لهذا المتصفح وملف المستخدم؛ لا توجد لوحة متصدرين على الإنترنت ولا تتم مزامنة النتيجة بين الأجهزة.
- قد تُفقد النتيجة عند مسح بيانات الموقع أو استخدام ملف متصفح مختلف.
- إذا لم يكن التخزين المحلي متاحًا، يستخدم الكود تخزينًا مؤقتًا داخل الذاكرة؛ وفي هذه الحالة لا تبقى النتيجة بعد إغلاق الصفحة أو إعادة تحميلها.

## كيف يعمل الكود

تم تقسيم منطق اللعبة إلى ملفات JavaScript صغيرة، ويجري تحميلها مباشرةً من HTML دون bundler أو إطار عمل:

| الملف | المسؤولية |
| --- | --- |
| **js/application.js** | نقطة بدء اللعبة؛ ينشئ مدير اللعبة بحجم 4×4 بعد طلب إطار الرسم التالي |
| **js/game_manager.js** | تنسيق دورة اللعب، وتوليد المربعات، والتحريك والدمج والنقاط والفوز وانتهاء الجولة |
| **js/grid.js** | بناء الشبكة، وفحص الخلايا الفارغة، وإدراج المربعات وإزالتها والتحقق من الحدود |
| **js/tile.js** | تمثيل المربع وقيمته وموقعه السابق والحالي ومعلومات الدمج |
| **js/keyboard_input_manager.js** | استقبال ضغطات لوحة المفاتيح والسحب باللمس، وإرسال أحداث التحريك وإعادة اللعب ومواصلة اللعب |
| **js/html_actuator.js** | عرض المربعات في DOM، وتحديث النقاط وأفضل نتيجة ورسائل الفوز والخسارة |
| **js/local_score_manager.js** | قراءة أفضل نتيجة وحفظها محليًا مع بديل مؤقت عندما لا يتوفر localStorage |
| **js/animframe_polyfill.js** | توفير بديل لـ requestAnimationFrame وcancelAnimationFrame عند عدم توفرهما |
| **js/classlist_polyfill.js** | توفير دعم classList للمتصفحات القديمة التي تحتاج إلى ذلك |

### تسلسل التشغيل

1. يحمّل المتصفح **index.html** والتنسيقات والأصول.
2. تُحمّل ملفات JavaScript بالترتيب المكتوب في أسفل HTML.
3. ينشئ **application.js** مدير اللعبة.
4. يبني **game_manager.js** شبكة اللعب، ثم يضيف مربعين ابتدائيين.
5. يستقبل مدير الإدخال الحركة ويرسلها إلى مدير اللعبة.
6. يُحدّث مدير اللعبة الشبكة والنقاط والحالة، ثم يعرض **html_actuator.js** النتيجة.

### قواعد المراحل والصور

الصورة **img/dbz_sprite.png** عبارة عن شريط أفقي بأبعاد **1391×107 بكسل**، مقسم إلى **13 خانة** متساوية، مقاس كل خانة 107×107 بكسل. يحدد CSS الجزء الظاهر من الشريط عن طريق **background-position** حسب قيمة المربع.

المراحل المعرّفة في CSS هي 2 و4 و8 و16 و32 و64 و128 و256 و512 و1024 و2048 و4096 و8192. تحتوي الخانتان الأخيرتان في النسخة الحالية على صور غوكو God وغوكو Blue.

## تشغيل اللعبة محليًا

اللعبة لا تحتاج إلى تثبيت حزم أو تشغيل عملية بناء.

### الخيار الأول: فتح الصفحة

افتح **index.html** في متصفح حديث. قد يختلف سلوك التخزين المحلي باختلاف المتصفح عند استخدام عنوان من نوع file://؛ لذلك يفضّل استخدام خادم ملفات محلي عند اختبار التخزين.

### الخيار الثاني: استخدام خادم محلي

إذا كان Python مثبتًا، افتح الطرفية في مجلد المشروع وشغّل:

~~~powershell
py -m http.server 8000
~~~

ثم افتح العنوان التالي في المتصفح:

http://localhost:8000

لإيقاف الخادم، ارجع إلى نافذة الطرفية واضغط Ctrl+C.

## النشر على GitHub Pages

المستودع عبارة عن موقع ثابت، وملف **index.html** موجود في الجذر؛ لذلك يمكن نشره مباشرةً دون عملية بناء.

1. افتح إعدادات المستودع: **Settings → Pages**.
2. في قسم **Build and deployment** اختر **Deploy from a branch**.
3. اختر الفرع **main** والمجلد **/(root)**.
4. اضغط **Save**.
5. انتظر انتهاء النشر الذي ينشئه GitHub، ثم افتح رابط الموقع الذي تعرضه صفحة Pages.

رابط الموقع المتوقع لهذا المستودع هو:

https://majd7772233-a11y.github.io/2048dbz/

يصبح الرابط متاحًا بعد تفعيل Pages واكتمال النشر بنجاح. إذا أجريت تغييرات على الملفات، فسيتم نشرها وفق مصدر النشر الذي تم اختياره في إعدادات Pages.

للمزيد، راجع [دليل GitHub Pages الرسمي](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## تعديل اللعبة

### تغيير حجم الشبكة

يُمرّر **js/application.js** الرقم 4 إلى مدير اللعبة، ما ينشئ شبكة 4×4. تعديل هذا الرقم وحده لا يكفي لشبكة أخرى؛ إذ تعتمد قواعد CSS الحالية على أربع صفوف وأربعة أعمدة ومواقع ثابتة للمربعات.

### تغيير نقطة الفوز

تُحدَّد نقطة الفوز في **js/game_manager.js** عند دمج مربع قيمته 2048. تغيير شرط الفوز يتطلب تعديل منطق اللعبة واختبار رسائل الفوز ومواصلة اللعب.

### تغيير الشخصيات أو مراحلها

عند تعديل **img/dbz_sprite.png**، حافظ على ترتيب الخانات وأبعادها ما دامت قواعد CSS تعتمد الإزاحات الحالية. إذا تغيّر العرض أو عدد الخانات أو حجم الخلية، فحدّث إزاحات **background-position** في **style/main.css** وكذلك إزاحات التنسيق المتجاوب للهواتف.

### تعديل المظهر

يجب اعتبار **style/main.css** ملف التنسيق الفعلي المستخدم في التشغيل. ملفات SCSS موجودة في المستودع، لكنها لا تُحوَّل تلقائيًا عند فتح الصفحة، كما أنها لا تعكس كل تخصيصات المظهر الموجودة في CSS الحالي. لا تعِد توليد CSS من SCSS دون دمج التخصيصات أولًا والتحقق من النتيجة.

- استجابة الأسهم وWASD وH/J/K/L.
- عمل السحب باللمس على شاشة هاتف.
- دمج المربعات الصحيحة وتحديث النقاط.
- تحديث أفضل نتيجة والاحتفاظ بها بعد إعادة تحميل الصفحة.
- ظهور شاشة الفوز عند الوصول إلى 2048 وعمل زر مواصلة اللعب.
- ظهور شاشة انتهاء الجولة عند عدم وجود حركات متاحة.
- صحة مظهر اللعبة على شاشة عريضة وعلى شاشة هاتف.
- تحميل الموارد من المسارات الصحيحة بعد النشر تحت مسار المشروع في GitHub Pages.

## الصور والأصول البصرية

تستخدم اللعبة صورًا لشخصيات وتحولات Dragon Ball جُمعت من الإنترنت، بما فيها الصور المدمجة في شريط **img/dbz_sprite.png**. لم تُنشأ جميع هذه الصور أصلًا لهذا المشروع، ولم تُوثق روابط المصدر الفردية لكل صورة داخل المستودع.

هذا مشروع معجبين غير رسمي. Dragon Ball وشخصياته وأسماؤه تعود إلى أصحاب الحقوق المعنيين؛ ولا يدّعي هذا المشروع ملكية تلك الشخصيات.

## ملاحظات تقنية

- لا يوجد خادم خلفي أو API خاص بالمشروع؛ منطق اللعبة والحفظ يعملان على جهاز اللاعب.
- زر المتابعة الذي يظهر في الصفحة مُضمَّن عبر iframe من خدمة **ghbtns.com**؛ قد يتأثر توفره بالخدمة الخارجية أو بمانعات المحتوى، دون أن يكون جزءًا أساسيًا من محرك اللعب.
- يوجد في كود العرض استدعاء اختياري لـ **ga** إذا كانت معرفة مسبقًا، لكن الصفحة الحالية لا تهيئ Google Analytics بذاتها.
- يعتمد عرض مراحل الشخصيات على ملفات CSS والصور المحلية، لذا يجب الحفاظ على المسارات النسبية عند النشر.
- لا يحتوي المستودع حاليًا على ملف ترخيص مستقل. هذا الملف التوثيقي لا يمنح ترخيصًا لإعادة استخدام الأصول الخارجية.
